# installer

Bootloader installation for every model: the older models through the partition patcher, the iPod Classic through DFU.

What is there so far (the older models, read only): the file of constants, the `SectorDevice` interface with its disk image implementation, the DOS and Apple partition tables, the check "is this disk an iPod" with the model, the choice among a given list of disks, the firmware partition (volume header, directory, image area, sizes, and the state `Clean`, `Installed` or `Inconsistent` with its message), and the check of the bootloader file.

Then the 8 checks before any write (`checks.h`, section 11): `runChecks()` runs them in order, stops at the first that fails and gives its message. Nothing is written to the disk; the only file made is the copy of the firmware partition of check 6, in a folder the caller gives. Check 7 is a warning. It is skipped for the 2nd generation nano and for an installed iPod, where the spec does not say what to compare (section 27). Check 8 follows the CMake option `TACETOS_ALLOW_REAL_WRITES` (OFF by default, ON only for the beta): a real disk is refused while it is OFF, a disk image file always passes.

The test device that fails at the n-th write is in `tests/installer/`.

Then the writes (`operation.h`, sections 13 to 17): `runOperation()` runs the checks, then install, update or uninstall of the bootloader, appended inside the OSOS image for every model but the 2nd generation nano, and as an image of its own after the last one for the 2nd generation nano (2048 byte sectors, Apple's entry kept as OSBK, one directory write for the two changes). Every write is whole sectors, flushed, read back and compared; Apple's firmware is never written again; the following images move from the end in pieces; the directory is one sector per change and is written after the data. On failure the result names the step (`WriteStep`) for the table of section 19. The install record and the final verification come later.

The iPod Classic (`dfuimage.h`, `docs/specs/bootloader-classic.md` sections 8 and 9): the four checks of the bootloader file in order, the installer image (sizes, bootloader header, single boot byte always 0 and no option to change it), the uninstaller image, and `checkInstallerImageReadyToSend()`, which the helper runs on the image it is about to send and which refuses a single boot byte that is not 0. The two fixed blocks and the two programs for the iPod are inputs, loaded from the folder of the CMake variable `TACETOS_DFU_PARTS_DIR` (outside the repository, made by CI: `header-signature.bin`, `certificate.bin`, `installer-payload.bin`, `uninstaller-payload.bin`). Without it the builder answers "Classic install is not available in this build". The tests use fake blocks and fake programs.
